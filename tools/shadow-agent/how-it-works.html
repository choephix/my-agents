shadow-daemon

How it works

A cheap observer of every finished turn in this OMP profile. Capture is free. Reasoning is one Luna call per session-batch. Memory lives in files, not in a long shadow transcript.

The split

Two processes, one package. They share a folder under the agent dir and almost nothing else.

Capture

A user-level extension, loaded in every session of this profile. On turn_end it appends a tiny pointer to a JSONL ledger. No model. No tools. If the daemon is off for a week, nothing is lost.

~/.omp/agent/extensions/shadow-ledger.ts

Daemon

A process you start yourself, one per job toml. It tails the ledger, slices the real session file, and wakes an ephemeral Luna session. Then it throws that session away.

bun shadow-daemon.ts examples/journal.toml

The original shadow-agent binary is still the other entry point: one session tree, one continuous shadow. This page is only the profile-wide daemon.

The path of one turn

1. You finish a turn The agent yields. OMP fires turn_end in the live session.
↓
2. Extension writes a pointer Only if this is a main session file under sessions/, and the assistant message actually settled (stop / length with no leftover tool call, or aborted / error). Subagents are skipped. Their work is already inside the parent turn as task results.
↓
3. Ledger grows by one line Something like: 
{"ts":"2026-08-16T18:40:00.000Z",
 "session":"/home/cx/.omp/agent/sessions/-workspace-nilo/….jsonl",
 "cwd":"/home/cx/workspace/nilo",
 "id":"…",
 "leaf":"…"}
No transcript. No prose. Just enough to find the turn later.
↓
4. Daemon tails that one file tailJsonl watches ~/.omp/agent/shadow-daemon/ledger.jsonl from this job’s bookmark. Each new line becomes a pending pointer, unless match_cwd rejects it.
↓
5. Dispatch picks one session-batch Pending pointers are grouped by session file. The first group whose newest turn is older than quiesce_secs (default 0) is ready. One wakeup at a time per job. If Luna is already running, new turns queue.
↓
6. Slice the real session Load the JSONL, walk the leaf branch, split at the first pending user turn: stripped backstory + full finished turn(s).
↓
7. One-shot Luna Fresh session in shadow-daemon-sessions/, cwd = the job’s files. Prompt = standing instruction + project label + prose + full turn. Luna reads/writes its own files, then the session is disposed.
↓
8. Bookmark advances The job cursor is the byte offset of the oldest still-pending ledger line, or the end of what has been seen. Restart resumes from there.

What Luna actually sees

Every wakeup is a new agent. There is no “remember last Tuesday from the transcript.” Continuity is whatever the job wrote to disk last time.

The system prompt is the job instruction plus a short standing rule:

  • You observe. You do not talk to Stefan.
  • Your working directory is the job’s files. Those files are your memory. Read them first, write them before you end.
  • Do the work and end the turn.

The user prompt is assembled in renderDaemonWakeup:

One finished turn in the session below.

project: nilo/worktrees/pr-9134
cwd: /home/cx/workspace/nilo/worktrees/pr-9134
session: /home/cx/.omp/agent/sessions/…jsonl
session id: …
job files: ~/.omp/agent/shadow-daemon/jobs/journal

## Conversation so far (stripped)
…user + assistant text only, via prose.ts…

## Finished turn(s) (full)
[@user]
…
[@assistant]
…including tool calls and results…

Act on your standing instruction now, then end your turn.

Stripped means the existing proseOf / storyFold from .omp/extensions/prose/prose.ts: user and assistant text, no thinking blocks, no tool noise. Full is the pending turn(s) with tools intact, so subagent work is visible where it matters and gone from the backstory.

Isolation: disableExtensionDiscovery, empty contextFiles / skills / rules. Luna does not inherit the observed project’s AGENTS.md. If it needs the project, the prompt gives the absolute cwd.

Scheduling, without a second scheduler

Default is strictly per-turn. quiesce_secs = 0 makes the age check vacuously true. The 500ms poll already exists as the tail backup, so debounce is one comparison: newest pending timestamp + quiesce ≤ now.

SituationWhat happens
Daemon idle, one turn lands One Luna call for that session, immediately (if quiesce is 0).
Two turns in two sessions Two Luna calls, sequential. One session-batch per call. Never mixed into one context.
Wakeup still running New pointers queue. After dispose, the next dispatch may send several turns from the same session as one lossless batch.
Daemon was off; ledger grew Resume from the job cursor. Keep the newest catchup_cap (default 100), drop older, log the drop.
shadow-daemon skip job.toml Bookmark → current ledger EOF. Exit. No reasoning.

Coalescing is backpressure, not policy. Fast daemon = one call per turn. Slow or returning daemon = catch up in batches that still contain every queued turn verbatim.

Files on disk

All of this is profile-local. Default profile:

PathRole
~/.omp/agent/shadow-daemon/ledger.jsonl Append-only pointers. Shared by every job in this profile.
~/.omp/agent/shadow-daemon/jobs/journal.cursor Byte offset into the ledger. Per job, so two daemons do not steal each other’s place.
~/.omp/agent/shadow-daemon/jobs/journal/ Luna’s default cwd and file memory. A job can set workdir to use another folder.
~/.omp/agent/shadow-daemon-sessions/ Throwaway one-shot transcripts. Outside sessions/, so the extension never recaptures them.

Other profile: --profile nilo switches the agent dir to ~/.omp/profiles/nilo/agent. There is no cross-profile daemon. The Nilo wall stays a wall.

Loop safety is the same trick as the original shadow: daemon sessions live next to, not inside, sessions/. The extension also refuses anything under shadow-daemon-sessions or shadow-agent-sessions.

A job is just a toml

name = "journal"
model = "openai-codex/gpt-5.6-luna"
workdir = "."
quiesce_secs = 0
catchup_cap = 100
max_cost_usd = 50
tools = ["read", "grep", "glob", "write", "edit"]

instruction_file = "journal.instructions.md"
  • name defaults to the filename. It is the cursor and default-workdir key.
  • workdir and instruction_file resolve relative to the job toml. Use either instruction_file or inline instruction, not both.
  • match_cwd is optional. Substring filter on the pointer’s cwd. The ledger is still written; the job just ignores the rest.
  • Budget is in-memory for this process. Hit $50 and the daemon exits nonzero. No persisted accounting.
  • No lockfile. Two daemons on the same toml will double-write the same job files. Don’t do that. Two daemons on different tomls is the point.

How to run it

Existing OMP sessions do not pick up a newly linked extension. Restart or reload those. New sessions write immediately.

# from shadow-agent/
bun shadow-daemon.ts examples/journal.toml
bun shadow-daemon.ts skip examples/journal.toml
bun shadow-daemon.ts --profile nilo jobs/decisions.toml

It does not start itself. You start the jobs you want, when you want them: a daily journal, a decisions file, a machine changelog — each a cheap Luna with its own instruction and its own folder.

What it is not

  • Not a continuous conversation that watches you across projects and “feels the chaos.” That design was rejected: cheap models degrade in long mixed transcripts. Chaos arrives as inputs; memory is files the job chose to keep.
  • Not a file-watcher over 1300 session JSONLs. One ledger, one tail.
  • Not automatic. No systemd unit, no hub start, no lock.
  • Not the original per-session shadow. That binary is still there for “watch this one tree, keep one shadow session.”
